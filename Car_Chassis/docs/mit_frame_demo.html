8 个字节怎么说话

达妙 DM-S2325-1EC 的 MIT 模式，一帧只有 8 个字节，却要塞进 位置、速度、Kp、Kd、前馈力矩 五个量。下面用四幕动画，把 量化 → 拼位 → 打包 → 一问一答 一次看完。

量化 · 物理值先变成整数

总线只能传整数。所以每个物理量都先按自己的量程映射成定点数： 位置和力矩是 16/12 位，速度 12 位，Kp、Kd 也是 12 位。 下面的滑杆就是主控里的 BSP_Motor_SetSpeed()， 拖一下，右边立刻算出真正要发出去的整数。

拼位 · 64 位怎么切

5 个量首尾相接，正好拼满 64 位：16 + 12 + 12 + 12 + 12 = 64。 每个格子是一位，亮的是 1，暗的是 0；颜色代表它属于哪个字段。 注意 速度、Kp、Kd、力矩 的 12 位都会跨过字节边界 —— 这正是打包时最容易写错的地方。

打包 · 8 个字节的真实顺序

把上面那条 64 位尺从左往右、每 8 位切一刀，就是 buf[0] 到 buf[7]。 颜色条显示每个字节里装的是谁的位 —— B3 和 B6 是拼接字节，高低半字节来自不同字段。

一问一答 · 发一帧才回一帧

MIT 是 query-based：主控发一帧控制，驱动器才回一帧反馈；不发就没有反馈。 所以 200 Hz 的控制周期，也就是 200 Hz 的反馈频率。反馈帧用的是 Master ID（左 0x11 / 右 0x12），跟控制帧的 ID 不是同一个。

三条必须记住的规则

协议之外，这三条最容易在实车上翻车。

① Kp = 0、Kd ≠ 0，主控别再套 PID

驱动器内部算的是 t = Kp·(p_des − p) + Kd·(v_des − v) + t_ff。 把 Kp 置 0，只剩 Kd·(v_des − v)，它本身就是一个速度 P 环。 主控只要送目标转速，再套一层速度 PID 会变成双闭环打架。

② 两个 ID 不是同一个

控制帧 ID = 电机 ID（左 1 / 右 2）； 反馈帧 ID = Master ID（左 0x11 / 右 0x12）。 出厂 Master ID 是 0，必须用达妙上位机改，否则总线上一片 0。

③ 一机一帧，不能合并

每帧只对一台电机说话，两台车就是两帧、两个 ID。 反馈也是各回各的，靠 data[0] 低 4 位的 ID 区分是谁在说话。
