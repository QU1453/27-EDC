# M2006 + C610 使用手册（精简）

> 适用：RoboMaster M2006 无刷电机 + C610 电调，CAN 总线控制。
> 本工程：STM32G473VET6 / FDCAN1 / 1 Mbps Classic CAN / 2 个电机差速底盘。

---

## 1. 硬件与接线

| 项目 | 内容 |
|---|---|
| 电机 | M2006 P36，编码器 13 位（8192 counts/rev），减速比 **36:1** |
| 电调 | C610，工作电压 24 V（6S），单路持续 10 A |
| 总线 | **Classic CAN（不是 CAN FD）**，固定 **1 Mbps** |
| 终端电阻 | C610 内部**没有** 120 Ω；总线两端各接一个 120 Ω |
| 线序 | CAN_H 红 / CAN_L 黑 / GND |
| 调试口 | C610 的串口与 CAN 口**不能同时接**（同一个接口复用） |
| 校准 | 首次使用需在 RoboMaster Assistant 里做**空载校准**，否则零点/方向异常 |

两条电机可以挂在同一条 CAN 上（ID 1~8），不需要两条总线。

---

## 2. 控制报文（主机 → 电调）

固定 8 字节，每 2 字节一个电机的电流值，**大端**，`int16`。

| 电机 ID | 帧 ID | 字节分配 |
|---|---|---|
| 1 ~ 4 | `0x200` | ID1=[0:1] ID2=[2:3] ID3=[4:5] ID4=[6:7] |
| 5 ~ 8 | `0x1FF` | ID5=[0:1] ID6=[2:3] ID7=[4:5] ID8=[6:7] |

槽位公式：`slot = (id - 1) % 4`。
同一帧里没用的槽位补 0。

```c
/* int16 打包成大端 */
uint16_t raw = (uint16_t)current;
buf[slot * 2]     = (uint8_t)(raw >> 8);
buf[slot * 2 + 1] = (uint8_t)(raw & 0xFF);
```

---

## 3. 反馈报文（电调 → 主机）

帧 ID = `0x200 + 电机ID`，即 `0x201 ~ 0x208`，固定 8 字节。

| 字节 | 内容 | 说明 |
|---|---|---|
| [0:1] | 机械角 | `uint16`，0 ~ 8191，转子侧，**上电从 0 开始** |
| [2:3] | 转速 | `int16`，单位 rpm，**转子侧** |
| [4:5] | 转矩电流 | `int16`，原始值 |
| [6] | 温度 | **C610 无此功能，数据无效** |
| [7] | 保留 | — |

多圈角度需要在主控里自己累加（单次跳变超过 4096 判为过圈）：

```c
int32_t diff = ecd - last_ecd;
if (diff >  4096) round_cnt--;
if (diff < -4096) round_cnt++;
total_ecd = round_cnt * 8192 + ecd;
/* 输出轴角度 = total_ecd / 8192 / 36 * 360 */
```

## 4. 量程与换算

| 电机 | 电流指令满量程 | 对应电流 |
|---|---|---|
| **M2006 + C610** | ±10000 | ≈ ±10 A |
| M3508 + C620 | ±16384 | ≈ ±20 A |
| GM6020 | ±16384 | ≈ ±3 A |

- 首测建议限流到 **±3000（≈3 A）**，确认方向、编码器、PID 都正常后再放开。
- 转子 rpm → 输出轴 rpm：除以 36。
- 转子 rpm → 车轮线速度：`v = rpm / 36 / 60 * 2πR`。
- 电流原始值 → 安培：`A = raw * 10.0 / 10000`。

## 5. 本工程参数

| 项目 | 值 |
|---|---|
| FDCAN 内核时钟 | PCLK1 = 170 MHz |
| 位时序 | Prescaler=10，Seg1=13，Seg2=3，SJW=1 |
| 结果 | 17 tq/bit，采样点 82.35%，**精确 1 Mbps** |
| 引脚 | PA11 = FDCAN1_RX，PA12 = FDCAN1_TX（AF9） |
| 时钟源 | `RCC_FDCANCLKSOURCE_PCLK1` |

> ⚠ CubeMX 当前生成的 `fdcan.c` 是 `Prescaler=16 / Seg1=1 / Seg2=1`（共 3 tq ≈ 3.54 Mbps），
> 且 `StdFiltersNbr=0`、`AutoRetransmission=DISABLE`。必须在 CubeMX GUI 里改，不要手改生成文件。

## 6. 代码分层

```
car_dipan/
├── App/            应用层：任务与业务逻辑
│   ├── app_config.h      所有可调参数（ID、方向、轮径、PID）
│   └── app_chassis.c/h   App_Chassis_Task()：收帧 → 运动学 → 速度环 → 下发
├── BSP/            板级支持层：外设封装，不参与业务
│   ├── bsp_can.c/h       FDCAN1 过滤/启动/收发（轮询）
│   └── bsp_motor.c/h     M2006/C610 电流打包、反馈解析、多圈角度
├── Algorithm/      数学工具层：纯算法，不依赖硬件
│   ├── algo_math.h       限幅/低通/映射/角度换算
│   ├── algo_pid.c/h      位置式 PID（积分限幅 + 抗饱和）
│   └── algo_kinematics.c/h  两轮差速正/逆解
├── Hardware/       屏驱动（已有）
├── Core/           CubeMX 生成，禁止手改
└── docs/           本手册
```

依赖方向：`App → BSP → Core/HAL`，`App → Algorithm`，`Algorithm` 不反向依赖任何层。

调用链（`main.c` 的 `while(1)` 里）：

```c
App_Chassis_Task();
  ├─ BSP_CAN_Recv()            轮询 FIFO0
  ├─ BSP_Motor_Decode()        解 0x201~0x208
  ├─ Algo_Chassis_Inverse()    底盘速度 → 左右轮目标 rpm
  ├─ Algo_PID_Update()         速度环
  ├─ BSP_Motor_SetCurrent()    限幅 ±3000
  └─ BSP_Motor_SendCurrent()   按 ID 分组发 0x200 / 0x1FF
```

控制周期 5 ms（200 Hz），由 `HAL_GetTick()` 做非阻塞节拍，不占用 SysTick 中断。

## 7. 首次上电调试顺序

1. **不装轮子**，电机空转；`MOTOR_SAFE_CURRENT_RAW = 3000`。
2. 上电先确认屏幕正常（说明主循环没被卡死）。
3. `App_Chassis_SetVelocity(0.0f, 0.0f)` 起步：此时 PID 目标 0，电机应该保持静止。
4. 给 `0.2 m/s`，确认**左右轮同向**：
   - 一侧反了就改 `APP_MOTOR_*_DIR` 为 `-1.0f`；
   - 两侧都反了就同时改。
5. 用 `App_Chassis_GetLeftRpm()` / `GetRightRpm()` 观察反馈是否跟随目标。
6. 方向、编码器都对上之后，再逐步放开限流、调 PID。
7. 最后装轮子落地，先低速直行，再试原地转（`w ≠ 0`）。

## 8. 故障排查

| 现象 | 排查点 |
|---|---|
| 电机完全不动、无反馈 | 位时序是否为 10/13/3；是否调用 `HAL_FDCAN_Start`；120 Ω；C610 是否上电/亮灯 |
| 有反馈但不动 | 控制帧 ID 是否发错（ID1~4 必须走 `0x200`）；电流是否被限幅成 0 |
| 只收到一个电机 | 两电机 ID 是否冲突；是否都在 `0x200` 组；槽位是否算错 |
| 转速飞车/振荡 | PID 极性反（目标减反馈应为负反馈）；`APP_MOTOR_*_DIR` 与编码器方向不一致 |
| 反馈转速符号与指令相反 | 电流方向与编码器方向定义相反，调 `_DIR` 或 PID 前加负号 |
| 上电就冲一下 | 积分初值/目标未清零；`App_Chassis_Init` 后应先 `SetVelocity(0,0)` |
| 偶发丢帧 | 控制周期不要低于 1 ms；总线负载过高时降频 |
